# 学習ループ: レビュー指摘・修正からの自己改善

PRレビュー指摘やユーザーの手動修正から一般化できる教訓を抽出し、ノイズなく蓄積する。実装スピードとトークン消費を優先し、学びが無ければ即座に何もせず終える。

## 発火条件（この2つ以外では発火しない）

1. PRレビュー指摘への対応がすべて完了し、pushし終えた直後
2. ユーザーが「直しておいた」「これ覚えておいて」「次から気をつけて」等で、Claudeを介さない自分の修正や指摘を明示的に共有したとき（`/record-learning` の明示呼び出しを含む）

通常の実装タスク完了時など、上記以外のタイミングでは絶対に発火しない。

## Step 1: 教訓の抽出（インライン・追加探索なし）

会話に既にある指摘内容・diffだけを見て、「このコード固有の話か、一般化できる教訓か」を1〜2文で言語化する。ファイル探索やサブエージェント起動は行わない。

- 汎用化できない（タイポ、その場限りの値の修正、一度きりの事情）と判断したら、ここで終了する。ユーザーに報告する必要もない
- 汎用化できる場合のみ Step 2 に進む

## Step 2: 分類

| 分類 | 判断軸 |
| ---- | ---- |
| プロジェクト規約候補 | 別の開発者や別セッションのClaudeがこのリポジトリで同じ作業をしても当てはまるコード規約・設計判断か |
| 個人の好み | リポジトリのコードではなく、Claudeとの協働の進め方（確認の要否・コミット粒度・報告の仕方など）についての好みか |

どちらとも言えない、または再発しなそうなら何もしない。

## Step 3: 記録

### 個人の好み

既存の自動memory機構にそのまま保存する（`feedback` タイプ、確認不要）。保存前に既存メモリと重複していないか通常どおり確認する。

### プロジェクト規約候補

1. 対象リポジトリの既存メモリ・CLAUDE.md・`.claude/rules/*.md` を検索し、同種の指摘が過去にも記録されているか確認する
2. **初出の場合**: 個人memoryに記録するだけに留める。プロジェクトファイルは編集しない
3. **2回目以降の再発の場合のみ**: 昇格対象として以下を行う
   1. 追記先を判断する（root `CLAUDE.md` / `front`・`back`・`mobile` それぞれの `CLAUDE.md` / 各リポジトリの `.claude/rules/*.md`）。既存ファイル・既存セクションの中で最も近い場所を優先し、無ければ新規ファイルを提案する
   2. diff形式で追加内容を提示し、「◯◯という指摘が2回目のため」のように一言で理由を添えてユーザーに承認を求める
   3. **承認を得るまで書き込まない**
   4. 承認後、コミットは以下の方針にする
      - 今アクティブな作業ブランチがあれば、そこに `Docs: ...` として1コミットで乗せる
      - main/デフォルトブランチしかない場合は、その場でブランチ・PRを作らず「別途Docsブランチを切って良いか」をユーザーに確認する（今の実装作業の速度を落とさないため）

## やらないこと

- 発火条件以外のタイミングでの実行
- 学びが無い場合のサブエージェント起動・余分な探索
- プロジェクトファイルへの無承認書き込み
- 個人の好みとプロジェクト規約の混同（どちらの方向にも）
- 初出だけでのCLAUDE.md/.claude/rules更新（再発確認前の先出し）
