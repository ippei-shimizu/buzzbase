## このPRDの狙い（なぜ作るか）

練習記録（PRD-05）と野球ノート（PRD-09）で「量・コンディション・感想・フォーム動画」という**上達の素材**は集まるようになった。しかし「記録している」と「上達している」の間には溝がある。素振り本数を積んで草が生えても、**課題意識のない反復は伸び悩む**。

本 PRD は、バラバラの記録を **「課題（テーマ）を決める → 練習する → データで効果を検証する → 次の課題へ」** という一本の上達ループに束ねる4機能を定義する。記録アプリを、選手にとっての **パーソナルコーチ** に引き上げることが目的。

対象4機能（本 PRD で一括管理し、実装は独立して着手可能）:

| ID | 機能 | 一言 | 依存 |
|----|----|----|----|
| F-A | 課題（テーマ）軸 | 取り組み中の課題を軸に練習・ノート・成績を束ねる | ループの土台。F-C/F-D の前提 |
| F-B | 相関インサイト | 練習量・コンディション × 成績を「言い切りカード」で見せる | 試合データ＋PRD-05 のログ |
| F-C | 振り返りテンプレ | 問いかけテンプレ（プリセット＋ユーザー自作）で内省の質を上げる | PRD-09 ノート保存フロー |
| F-D | 週次/月次レポート | がんばりと課題進捗、成績変化を自動で振り返る | F-A / F-B の集計を流用 |

> スコープ外（今回は保留）: フォーム動画の Before/After 比較・定点観測 / コーチ・親へのノート共有。将来 Phase として別途検討する。

# F-A: 課題（テーマ）軸

## 背景・目的

本気の選手は常に1〜2個の「今取り組んでいる課題」を持っている。記録を課題に紐付けることで、日々のログが **「1つの課題を潰しにいく物語」** に変わり、継続の意味づけが強くなる。JTBD「もっと上手くなりたい」「諦めない」の中核。

## ユーザーストーリー

- US-A1: 翔太は「肩の開きを抑える」を課題に設定。以降の練習セッションとノートをこの課題に紐付け、ホームで「取組14日目・関連ノート3本・関連練習8回」を確認して手応えを感じる。
- US-A2: 翔太は3週間後、課題を「克服した」でクローズ。履歴に達成として残り、次の課題「引きつけて打つ」を新規に設定する。

## 機能要件

| # | 機能 | 詳細 |
|---|----|----|
| FA-01 | 課題の作成・編集・削除 | 名前（必須）／カテゴリ（PRD-05 のカテゴリを流用）／任意メモ・目的 |
| FA-02 | 状態管理 | `open`（取組中）/ `achieved`（克服）/ `archived`。克服時に達成日を記録 |
| FA-03 | 記録との紐付け | 練習セッション・ノートに課題を紐付け（任意・複数不可＝1記録1課題）。保存フローで直近の open 課題をプリセット |
| FA-04 | 取組サマリー | 課題ごとに 取組日数・連続日数・関連練習数・関連ノート数を集計表示 |
| FA-05 | ホーム常設カード | 「今取り組んでいる課題」を活動セグメント上部に常設。open が無ければ設定を促す空状態 |
| FA-06 | 課題履歴 | 克服・アーカイブした課題を一覧（達成の勲章として残す） |

## 無料 / Pro

| 項目 | 無料 | Pro |
|----|----|----|
| 同時 open 課題数 | 1つ | 無制限（推奨1〜2） |
| 課題履歴の閲覧 | 全期間 | 全期間 |
| 課題×成績の相関（F-B 連携） | × | ◎ |

## データモデル


# F-B: 相関インサイト（練習量・コンディション × 成績）

## 背景・目的

PRD-05 の F-21「練習量と成績の相関グラフ（Pro/Phase2）」を具体化する。**グラフを出すだけでは中高生に刺さらない**ため、**言い切りのインサイトカード**として提示する。自分のデータでしか得られない発見が、継続とProの最強レバーになる。

## ユーザーストーリー

- US-B1: 「素振りを週1500本以上やった週は、打率が .045 高い」というカードを見て、素振りの意味を実感し継続する。
- US-B2: 「睡眠6時間未満が続いた週は三振率が上がっている」に気づき、生活を見直す。

## 機能要件

| # | 機能 | 詳細 |
|---|----|----|
| FB-01 | インサイトカード生成 | 週次で「練習量/コンディション」と「成績指標」の関係を自然文カードで提示 |
| FB-02 | 対象の掛け合わせ | 練習量（総素振り数・メニュー別）・睡眠・疲労・体調 × 打率/OPS/三振率/防御率 等 |
| FB-03 | 課題連携（F-A） | open 課題に紐付く練習量とその課題領域の成績を優先的に相関表示 |
| FB-04 | データ不足時の扱い | サンプル週が閾値未満なら断定せず「もう少しデータが集まると分かる」表示にする |
| FB-05 | 根拠の開示 | カードをタップで元の推移（該当週の練習量と成績）を確認できる |

## 算出方針（要件レベル。詳細は Design Doc）

- 週（JST 月〜日）単位で「入力量（説明変数）」と「成績（目的変数）」を集計し、上位群/下位群の平均差、または相関の符号・強さで文言テンプレを選ぶ。
- **因果ではなく傾向**であることを明示（誤解を招く断定を避ける）。統計的に弱い/サンプル不足は FB-04 で握りつぶさず正直に出す。
- 対象成績は既存の集計（打率・OPS・三振率・防御率 等）を再利用。新規指標は作らない。

## 無料 / Pro

| 項目 | 無料 | Pro |
|----|----|----|
| 相関インサイト | × | ◎ |

> 無料では「Pro なら“あなたの素振りと打率の関係”が分かる」と訴求（カード枠だけ見せてロック）。

# F-C: 振り返りテンプレ（問いかけ）

## 背景・目的

自由メモ欄は「何を書けばいいか分からない」ため質が上がらない。**問いかけ形式のテンプレ**で内省を構造化し、書く負担を下げつつ質を上げる。テンプレは**プリセットから選べる**＋**ユーザー自身が作れる**。

## ユーザーストーリー

- US-C1: 練習保存直後のノート誘導で、翔太は「うまくいったこと / 課題への手応え / 次やること」テンプレを選び、空欄でなく問いに答える形で振り返る。
- US-C2: 拓海は自分用に「今日のフォーム意識」「1本、良い当たりは？」というオリジナルテンプレを作り、以後それを既定にする。
- US-C3（将来拡張・初期リリース対象外）: 「次やること」に書いた内容が、翌日の練習セッション作成時に引き継ぎ表示される（ループが閉じる）。

## 機能要件

| # | 機能 | 詳細 |
|---|----|----|
| FC-01 | プリセットテンプレ | 運営提供の問いかけセットを複数用意（下記）。選ぶとノートに問い付きの入力欄が展開 |
| FC-02 | テンプレ選択 | ノート/振り返りメモ入力時にテンプレを選択。既定テンプレをユーザーが指定可 |
| FC-03 | ユーザー自作テンプレ | 問い（複数行）を自由に定義して保存・編集・削除・並び替え |
| FC-04 | 回答の保存形式 | 「問い→回答」の構造で保存し、閲覧時も問い付きで表示 |
| FC-05 | 「次やること」の引き継ぎ（将来拡張） | 直近ノートの「次やること」を翌練習セッション作成時にプリセット表示（F-A と連携）。**初期リリースでは実装しない**: 消化（完了）のライフサイクルが未設計のまま出すと古い宣言が表示され続けてノイズになるため、ノート運用の定着後にライフサイクル込みで再設計する |

### プリセットテンプレ（初期案・確定は実装時）

- ふりかえり3行（KPT系）: 「うまくいったこと」「課題」「次やること」
- 課題フォーカス: 「今日の課題への手応え（◎○△）」「気づき」「次に試すこと」
- 試合後: 「良かった打席/投球」「悔しかった場面」「次戦への修正点」
- コンディション重視: 「体の状態」「疲れの原因」「ケアすること」

## データモデル

```ruby
class CreateReflectionTemplates < ActiveRecord::Migration[7.1]

    create_table :reflection_templates do |t|
      t.references :user, foreign_key: true          # null = 運営プリセット
      t.string  :title, null: false
      t.json    :questions, null: false, default: [] # ["うまくいったこと", "課題", "次やること"]
      t.boolean :is_preset, default: false
      t.boolean :is_default, default: false          # ユーザーの既定テンプレ
      t.integer :sort_order, default: 0

```

- ノート側は回答を構造化保存する。既存 `baseball_notes` の本文と両立させるため、`reflection_answers`(json: `[{question, answer}]`) と `reflection_template_id`(nullable) を `baseball_notes` に追加する（テンプレ未使用時は従来どおり自由メモ）。

## 無料 / Pro

| 項目 | 無料 | Pro |
|----|----|----|
| プリセットテンプレの利用 | ◎（全プリセット選択可） | ◎ |
| ユーザー自作テンプレ | 1つまで | 無制限 |

> 振り返りの入口は無料でも開けておき（習慣化を優先）、**自作テンプレの複数保有**を Pro レバーにする。

# F-D: 週次/月次 振り返りレポート

## 背景・目的

日々の記録を、週末/月末に**自動でひとまとめの振り返り**にして返す。がんばりの承認（Streak/量）と、課題進捗・成績変化・次の一手を一枚で見せることで、回顧の報酬と次サイクルの起点を作る。

## ユーザーストーリー

- US-D1: 日曜夜、翔太に「今週：練習6日・素振り2100本・課題『肩の開き』に4日・打率先週比 +.030」というレポートがアプリ内に生成され、来週の一手が提案される。
- US-D2: 月末、拓海は月次レポートで「最も伸びた指標」「最も取り組んだ課題」を振り返る。

## 機能要件

| # | 機能 | 詳細 |
|---|----|----|
| FD-01 | 週次レポート生成 | 週（JST 月〜日）締めで集計: 練習日数・Streak・総量・課題別取組・コンディション平均・成績の前週比 |
| FD-02 | 月次レポート生成 | 月締めで同様＋「最も伸びた指標」「最も取り組んだ課題」 |
| FD-03 | 相関インサイト同梱（F-B） | その期間の代表的インサイトカードを1枚同梱 |
| FD-04 | 次の一手の提案 | 課題進捗・データから軽い提案文（例: 「睡眠が短い週が続いています」） |
| FD-05 | アプリ内表示 | 起動時に未読レポートをカード/モーダルで表示。バックナンバー閲覧可 |

> 通知方針: PRD-07 同様、MVP では**サーバー push を出さず**アプリ内表示のみ（`#324` 方針に合わせる）。将来 push は延期。

## データモデル

```ruby
class CreatePeriodicReviews < ActiveRecord::Migration[7.1]
```

## 無料 / Pro

|----|----|----|
| 週次レポート（基本: 量・Streak・練習日数） | ◎ | ◎ |

## 連動仕様（全体）

- **草 / Streak（PRD-04）**: F-A の課題紐付けや F-C のテンプレ回答は草の強度に影響させない（量ログのみが強度を決める既存方針を維持）。
- **目標（PRD-07）**: 課題（テーマ, 短期の技術フォーカス）と目標（成績・行動の到達値）は別概念。将来、目標達成サマリーとレポート（F-D）を統合表示する余地を残す。
- **推移グラフ（PRD-06）**: F-B の相関カードの「根拠を見る」で既存推移チャートへ遷移する。
