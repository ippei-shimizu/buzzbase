## 概要

GitHub のコントリビューショングラフのように、練習や試合をした日に色がついていくヒートマップカレンダー。
連続日数（Streak）と累計練習日数を視覚的に表示し、「諦めない」気持ちを支える。

---

## UI/UX・集約契約 確定事項（2026-06-27）

設計検討で確定。以降の「データモデル」「強度レベルの定義」と差異がある場合は**本セクションを優先**する。
本機能は activity_logs（草・Streak の集計基盤）の**正本**であり、練習記録（PRD-05）・素振り（PRD-03）・試合がここへ集約される。

### activity_logs（案A: 集計テーブルで確定）

- ユーザー×日付の集計テーブル。practice_log / game_result / shadow_swing の書き込み時に **after_commit でその日分を再計算**（案B のビュー都度集計は不採用）
- 保持カラム: `practice_menu_count`（distinct メニュー数）/ `total_swing_count` / `has_game` / `intensity_level`(0〜4)
  - ※ 当初スキーマの `activity_count` は `practice_menu_count`（distinct）に置き換える
- **コンディションログ（condition_logs）は集計対象外**（休養日でも記録するため、草を生やさない）
- 日付は JST ローカル。過去日の追加・編集時はその日を再集計

### 強度レベル（「アクティビティ」= distinct メニュー数 と明確化）

L0=なし / L1=メニュー1種 / L2=2種 or 素振り100本+ / L3=3種 or 300本+ / L4=4種+ or 500本+ or 試合あり

### 配色（緑グラデーション）

ダークテーマ上の緑濃淡（L0=グレー → L4=最濃緑）。ブランドゴールドではなく「草=green」の比喩を優先する。

### ホームの草ミニ と 無料境界（2026-07-29 更新）

- ホームのサマリーカードは取得できた範囲（無料は直近30日、Pro は全期間）をそのまま表示する。セルタップで日付・内容のキャプションを表示する
- 「直近12週固定表示＋30日より前のセルを淡色ロック」は一度実装したが、issue #446 で機能自体が不要と判断されクローズ（詳細は「実装状況」節）。ホームは上記のシンプルな表示のまま確定とする

### Streak 途切れ通知（F-07、2026-07-29 更新）

- 当初仕様: その日 `intensity_level=0` のまま夜（例: 20時）になったら「今日まだ草が生えていません」を送る。**Streak 保持中（連続記録がある）ユーザーにのみ**送信し、連続0日のユーザーには送らない（通知過多を避ける）
- 現状の実装は端末のローカル通知（日次リピートトリガー）のみで、上記の「その日20時時点の動的判定」はサーバー側では行っていない。サーバー側是正を issue #447 で検討したが、機能自体が不要と判断されクローズ。ローカル通知の実装のまま運用する

## 背景・目的

- 戦略ドキュメントのステップ11 で MVP に採用
- 競合に存在しない独自機能
- 視覚的な「ここまで来た」を提供
- 損失回避バイアス（途切れさせたくない）を活用
- SNS バイラル素材（「1年分の草」シェアで拡散）

---

## ユーザーストーリー

### US-01: 大輝（大学野手）の継続モチベ

> 大輝は毎日素振りを継続している。アプリのホーム画面で「草」を見るたび「今日も練習しよう」と思える。
> 365日連続記録に挑戦中で、途切れさせたくない一心。

### US-02: 健（社会人野手）の振り返り

> 半年に1回、自分の「草」を見て「これだけ頑張ってきた」と自己肯定感を得る。
> SNS にシェアして、フォロワーと交流。

## データモデル

### activity_logs テーブル（新規 or 集計ビュー）

既存テーブル（practice_logs, game_results, shadow_swing_sessions）から集計するか、
パフォーマンスのため集計テーブルを用意する。

#### 案A: 集計テーブル

```ruby
class CreateActivityLogs < ActiveRecord::Migration[7.0]
  def change
    create_table :activity_logs do |t|
      t.references :user, null: false, foreign_key: true
      t.date :activity_date, null: false
      t.integer :activity_count, default: 0   # その日のアクティビティ総数
      t.integer :intensity_level, default: 0  # 0:なし, 1:軽い, 2:普通, 3:多い, 4:非常に多い
      t.json :sources                         # {"practice": 2, "game": 1, "shadow_swing": 200}
      t.timestamps
    end

    add_index :activity_logs, [:user_id, :activity_date], unique: true
  end
end
```

#### 案B: 既存テーブルから集計（ビューまたはクエリ）

毎回 SQL で集計（パフォーマンス次第で案Aへ移行）

### Streak 集計

```ruby
class User < ApplicationRecord
  def current_streak_days
    # 今日から逆に遡って連続日数をカウント
    activity_logs
      .where('activity_date <= ?', Date.current)
      .order(activity_date: :desc)
      .each_with_index do |log, index|
        expected_date = Date.current - index.days
        return index if log.activity_date != expected_date
      end
  end

  def longest_streak_days
    # 最長連続記録
  end
end
```

## 強度レベルの定義

| レベル | 色 | 条件 |
|------|--|----|
| 0 | グレー | 練習なし |
| 1 | 薄緑 | 1アクティビティ |
| 2 | 中緑 | 2アクティビティ or 素振り100本以上 |
| 3 | 濃緑 | 3アクティビティ or 素振り300本以上 |
| 4 | 最濃緑 | 4アクティビティ以上 or 素振り500本以上 or 試合あり |

## エッジケース・エラーハンドリング

| ケース | 対応 |
|------|----|
| 過去データを後から追加 | activity_logs を再集計 |
| 同じ日に複数アクティビティ | activity_count を増やす、source に集約 |
| タイムゾーンを跨ぐ記録 | ユーザーのタイムゾーン（JST）で集計 |
| Pro解約後 | 直近30日のみ表示に切り替え（過去データは保持） |
