## Background

Pro機能の MVP は7機能（素振りカウンター / 草機能ヒートマップ / 練習記録 / シーズン推移グラフ / 目標設定・達成管理 / 自主練スケジュール・リマインド / 野球ノート拡張）で、その多くが「練習」に関わる。
既存アプリは「試合中心」の5タブ（ダッシュボード / 試合結果 / 成績 / グループ / マイページ）で構成されており、練習という第2の柱が存在しない。
各機能 PRD は機能要件中心で、**画面構成・ナビゲーション・情報設計（IA）の方針はほぼ未定義**。各機能を個別実装する前に、横断する IA と体験の骨格を固める必要がある。

なお Pro機能の設計（2026-05時点）後に **新打撃記録・分析機能** が実装され、当時より詳細な分析（状況別打率・打球の質・球種別など）と、試合/月単位の打撃推移グラフ（`BattingTrendChart`）・防御率推移グラフ（`EraTrendChart`）が既に存在する。本ドキュメントはこの現状を前提に設計する。

---

## Goals

- 練習系 Pro機能を一級市民に引き上げる IA（タブ間取り・画面の置き場）を確定する
- 「毎日開く理由（継続のループ）」を最小摩擦で回す画面構成を定義する
- 練習記録・野球ノートの役割境界と、両者の紐付け体験を確定する
- シーズン推移グラフを既存チャートの拡張として位置づける
- 無料 / Pro 境界を画面のどこに出すかを定義する

## Non-goals

- 各機能の詳細実装仕様（API・テーブル定義は各機能 Design Doc / PRD で詰める）
- Android / 広告（AdMob）まわりの UI（一旦対象外）
- ビジュアルデザイン（配色・余白・コンポーネント詳細）

## 設計原則

1. **継続レイヤー（Streak / 草）を全機能の接着剤にする**
   素振り・練習記録・試合がすべて `activity_logs` に集約され Streak / 草を育てる。これは個別機能ではなく横断する1つのシステム。常に目に入る位置に置き「今日も途切れさせたくない」を毎回見せる。
2. **7機能を「記録する / 続ける / 振り返る」の3レイヤーに束ねる**（バラバラの7画面として作らない）。
3. **デイリーループを最小摩擦で回す**
   `通知（スケジュール）→ 練習 → 素振り → 自動で練習ログ＆草が育つ → 進捗を見て満たされる → 草をSNSシェア`。このループの導線設計を最優先する。
4. **無料 / Pro 境界をUIに最初から織り込む**
   素振り基本無料・草30日無料・メニュー3つ無料 等「部分無料」が多い。ロック状態・「Proで全期間」・リワード広告チラ見せを後付けでなく画面設計に内包する。

### 機能の3レイヤー整理

| レイヤー | 機能 | 利用文脈 / 頻度 | 置き場所 |
|---|---|---|---|
| 記録する | 練習記録 / 野球ノート / 素振りカウンター | 練習中・練習直後（毎日） | 練習・活動面の最上段ボタン（素振りは「練習ツール」） |
| 続ける | 草ヒートマップ / Streak / スケジュール＋リマインド | 毎日開く・通知起点 | 練習・活動面の「今日のやること」「継続」＋通知 |
| 振り返る | シーズン推移グラフ / 目標設定・達成 / 定期レビュー | 不定期・月初/月末・シーズン境 | 成績タブ / 練習・活動面の「目標管理」「週次・月次の振り返り」 |

## Detailed Design

### 1. 情報設計（IA）

ボトムタブは**現状5つを維持**し、`ダッシュボード` タブを **「ホーム」** にリネーム。ホーム内をセグメントで2面に分け、練習・継続を一等地に置きつつ既存のダッシュボードも温存する。

```
ボトムタブ（5・現状維持）
┌─────┬─────┬─────┬───────┬─────┐
 ホーム  試合  成績  グループ  マイ
   │
   └─ ホーム内セグメント（練習・活動をデフォルト表示）
      ┌──────────────┬──────────────┐
      │  練習・活動   │  ダッシュボード  │
      └──────────────┴──────────────┘
```

- **タブ名**: `ダッシュボード` → `ホーム`
- **セグメント**: `[練習・活動] ⇄ [ダッシュボード]`。デフォルトは **練習・活動**（毎日のループを毎回見せるため）
- 既存の `成績` タブはそのまま（深い分析・推移グラフを担当）
- `グループ` / `マイページ` も現状維持

#### 各機能の置き場マップ

| 機能 | 置き場 |
|---|---|
| 草 / Streak | ホーム > 練習・活動「継続」セクション（記録・今日やることの下）＋ 詳細はスタック下 |
| 自主練スケジュール | ホーム > 練習・活動「今日のやること」＋ 週プラン / カレンダーはスタック下 |
| 素振りカウンター | ホーム > 練習・活動「練習ツール」→ `(shadow-swing)` の設定・実行画面 |
| 練習記録 | ホーム > 練習・活動 最上段の記録ボタン → `(practice-record)/daily`（日付＋複数メニュー＋コンディション＋課題） |
| 野球ノート | ホーム > 練習・活動 最上段の記録ボタン → `(note)/new`。一覧は `(records)/list`（練習記録と同居） |
| 目標設定・達成 | ホーム > 練習・活動「目標管理」＋ 一覧・設定はスタック下 |
| 課題テーマ / 振り返り | ホーム > 練習・活動「上達サイクルをまわす」＋ 定期レビューはバナー導線 |
| シーズン推移グラフ | 成績タブ（既存チャートの粒度拡張、後述） |

### 2. 「練習・活動」面の画面構成

継続ループの司令塔。初版は「継続 → 今日やる → 記録」の順だったが、実装では **記録導線を最上段に固定**し、「記録 → 今日 → 継続（報酬）→ 振り返り → ツール → 積み上げ」の順に組み替えた。毎日開いた瞬間に「記録する」へ最短で到達させることを優先している。

```
┌──────────────────────────────────┐
│ ホーム                  🔔   ⚙️   │
│ ┌─[練習・活動]─┬─ ダッシュボード ─┐│
│                                   │
│  [🏋️ 練習を記録] [✍️ 野球ノートを記録] │ ① 記録ボタン（最上段・カード無し）
│   練習記録・野球ノートの一覧 →     │    一覧は (records)/list に集約
│                                   │
│  ── 今日のやること ───────────    │  ② 今日のスケジュール
│  ☐ 06:00  朝の素振り 200本    ▶  │     空なら「スケジュールを設定」CTA
│                                   │
│  ── 取り組み中の課題 ─────────    │  ③ 現在の課題テーマ
│  ── 目標管理 ─────────────────    │  ④ 目標進捗 → 目標一覧/設定
│  ── 継続 ─────────────────────    │  ⑤ Streak＋草ヒートマップ
│  🔥 連続 15日   ▓▓▒░▓▓▓░▒▓▓▓      │     無料は直近30日／Proは全期間
│  ── 週次・月次の振り返り ─────    │  ⑥ 定期レビューのバナー
│  ── 練習ツール ───────────────    │  ⑦ 素振りカウントタイマー
│  ── 上達サイクルをまわす ─────    │  ⑧ 課題・振り返り・インサイト導線
│  ── 今月の積み上げ ───────────    │  ⑨ 月次サマリー
│  ── 最近の練習 ───────────────    │  ⑩ 練習タイムライン入口
│  すべての練習ログを見る →          │
└──────────────────────────────────┘
```

設計の狙い:
- 練習系 Pro機能（素振り・練習記録・ノート・スケジュール・草/Streak・目標・課題・振り返り）をこの1面に集約。バラバラの画面に散らさず、毎日の動線を1スクロールに収める。
- ①記録ボタンが主役。「開く → 即記録 → 草が育つ → ⑤で達成感」のループを最短化。
- 詳細・管理系（草の全期間、スケジュール編集、目標設定、練習ログ一覧、ノート編集）はスタック下に逃がし、この面は「ハブ」に徹する。

### 3. 記録の導線（実装版）

初版は「クイック記録の4ボタン」を想定したが、実装では最上段を **2ボタンに絞り**、素振りは「練習ツール」セクションへ分離した。お気に入りメニューのワンタップ記録（`＋素振り200` 等）は採用していない。
**コンディションは独立導線をやめ、`練習を記録`（日次セッション）の中の section に内包する。**

| 導線 | 置き場 | 役割 |
|---|---|---|
| 🏋️ 練習を記録 | 最上段ボタン | **1日分**を記録: 日付＋複数メニュー（回数）＋コンディション（Pro）＋取り組む課題＋振り返りメモ。後日入力可 |
| ✍️ 野球ノートを記録 | 最上段ボタン | その日の感想・気づき・動画を残す（定性）。練習記録（定量）と分離し、日単位で緩く紐付く |
| 練習記録・野球ノートの一覧 | 最上段ボタン直下のリンク | 量ログと定性ノートを同じ一覧（`(records)/list`）で振り返る |
| 素振りカウントタイマー | 「練習ツール」セクション | 素振りをリアルタイム計測（リズム音＋自動カウント）。完了時に練習ログを生成 |

> コンディション（疲労・体調・睡眠・気分・怪我）は `練習を記録` 内の Pro 限定 section。
> 単独の体調記録画面・ボタンは持たない。

### 4. 練習記録 と 野球ノート の境界

両者はメモ・写真を持つため混同されやすいが、**役割が根本的に異なる**ため統合せず別データとして保つ。

| 観点 | 練習記録（定量ログ） | 野球ノート（定性日誌） |
|---|---|---|
| 主役 | 数値（量）回数/時間/距離 | 文章・動画（気づき・指摘・フォーム） |
| 目的 | 行動の蓄積・習慣化 | 思考の蓄積・改善 |
| 入力 | サッと（ワンタップ〜数値） | じっくり（書く・撮る） |
| 頻度 | 毎日・練習のたび | 不定期（学びがあった時） |
| メモ/写真 | 一言の補足（任意） | 本体（メモ・動画こそが中身） |
| 草/Streak連携 | する（activity_logs に流れる） | しない |
| 試合との紐付け | 練習が対象 | 試合にも紐付く（PRD-09） |

例えると、練習記録＝フィットネスアプリの「ワークアウトログ（今日5km走った）」、野球ノート＝「コーチングノート（フォームのここを直す、と書く）」。

### 5. 練習記録 ↔ 野球ノートの紐付け（モデルA: 緩い紐付け＋保存後誘導）

「練習中に感じたこと・教わったこと（どんな感覚だったか）」をノートに残し、その日の練習に結びつけたい、という体験を満たす。

**原則: データは別のまま、ノート側に「紐付け先」を持たせて結ぶ**
- 練習記録（定量・草に流れる）と野球ノート（定性・動画）は分離したまま
- 野球ノートが「練習日（または特定の練習ログ）」を参照する。試合への紐付け（PRD-09で既存）に加えて「練習への紐付け」を足す形

**体験のコア: 練習保存と同時のノート誘導（実装では保存ボタンの2択で実現）**

初版は「保存後に確認モーダルを挟む」案だったが、実装では**保存ボタン自体を2つ並べる**形に簡略化した。モーダルを挟まないぶん、ノートを書かない日の摩擦がゼロになる。

```
練習を記録（量）の入力画面 下部
┌──────────────────────────────┐
│ [ 野球ノートを書く ]           │ ← 保存 → ノート新規画面へ（練習が自動で紐付く）
│ [ 練習記録のみ保存 ]           │ ← 量だけ残して終了
└──────────────────────────────┘
        ↓ 「野球ノートを書く」
┌──────────────────────────┐
│ 野球ノート（新規）         │
│ 紐付け: 🏋️ 6/27の練習 ▼    │ ← 自動で今日の練習セッションが入る
│ メモ [外角が体の開きで…]   │
│ 写真/動画 [🎥＋]           │
│ [保存]                    │
└──────────────────────────┘
```

**紐付けの粒度**
- **日単位（その日の練習セッション）** で確定。`baseball_notes` が `practice_session_id` を nullable 参照する
- 「今日の練習全体の感想」という自然な単位に揃え、特定メニュー（個別の練習ログ）への紐付けは採用していない

**表示: 練習・活動面の日付タイムライン（量と感想が同居）**

```
── 6/27(木) ──────────────
 🏋️ ティー150球 ・ ラン5km     ← 練習記録（量・チップ）
 ✍️「外角が体の開きで詰まる。
     右肩を我慢、と指摘」       ← 紐付いた野球ノート（感想）
     🎥 フォーム動画
─────────────────────────
── 6/26(水) ──────────────
 🏋️ 素振り200
 （ノートなし）
```

**緩い紐付けである点が重要**
- ノートは練習に紐付かなくても書ける（試合だけに紐付く／ただの日記としても）
- 練習記録だけ残して感想なしの日もOK（「あとで」で量だけ残す）
- 必須の連結ではなく「結びたい時に結べる」緩い関係にして入力負担を増やさない

> データの持ち方は `baseball_notes.practice_session_id`（nullable 参照）で確定。join テーブルは切っていない。

### 6. シーズン推移グラフ = 既存チャートの粒度拡張

PRD-06 は当初「新規画面＋新API（`/stats/season_transition`）」を前提に書かれたが、Pro設計後に試合/月単位の推移グラフが既に実装されたため、**新画面を作らず既存チャートを拡張する**方針に変更する。

| 項目 | 内容 |
|---|---|
| 打撃 | 既存 `BattingTrendChart`（試合/月、4ライン: 打率/OBP/SLG/OPS）に粒度 **「シーズン」「年」** を追加＋自己ベスト強調 |
| 投手 | 既存 `EraTrendChart`（現状: 月単位の防御率のみ・単線）に **粒度切替（試合/月/シーズン/年）** を新設＋自己ベスト強調。打撃側より着手量が多い（粒度切替UI自体が未実装） |
| 置き場 | 既存 **成績タブ**（推移グラフがある場所）。新規 Pro 画面は作らない |
| 無料 / Pro | 試合・月（ズームイン）= **無料** ／ シーズン・年（横断）= **Pro** |

利点:
- ほぼ同じグラフが2つできて「どっちを見ればいいの？」となるのを防ぐ
- 実装は粒度1つ追加＋集計クエリ追加で済み、新規画面より軽量
- 新分析で増えた指標（打球の質・状況別など）も将来この同じ推移基盤に乗せられる

> PRD-06 の「完全に Pro 限定（無料では一切閲覧不可）」は本方針で更新される（試合/月のズームインは無料）。詳細は PRD-06 の更新ノート参照。

### 7. 無料 / Pro 境界マップ

各セクションに Pro 境界が自然に同居するため、無料ユーザーにはその場でロック＋Pro導線を出せる（後付けにしない）。

以下は本ドキュメントが扱う練習系 IA の範囲での境界。**機能キーの正は `back/app/models/concerns/entitlement.rb`（および `mobile/types/pro.ts` / `front/app/types/pro.ts`）**で、そちらには打撃分析・グループ・広告非表示など IA 範囲外を含む全 Pro 機能が定義されている。Paywall の比較表もこのキー定義から生成される。

| 機能 | 無料 | Pro | ロックを出す場所 |
|---|---|---|---|
| 草ヒートマップ | 直近30日 | 全期間 | ホームのヒートマップをそのまま表示（年ビュー・画像エクスポートはissue #446で不要と判断し見送り。詳細: PRD-04「実装状況」） |
| スケジュール | 作成数は無制限 | 来週へ一括コピー / カレンダー全期間閲覧 / カスタム通知メッセージ | 週プランのコピー操作時・カレンダーの過去月移動時・通知文言の編集時 |
| 練習メニュー | 3件 | 無制限 | メニュー追加時 |
| メニューセット | 2件 | 無制限 | セット追加時 |
| コンディション | × | ○ | 練習を記録 内のコンディション section |
| 写真・動画添付 | 月3件 | 無制限 | 添付上限到達時 |
| 課題テーマ | 取組中2件 | 無制限 | 課題テーマ追加時 |
| 課題の紐付け | 1件 | 複数件 | 練習記録・ノートの課題選択時 |
| ノートのタグ | × | ○ | ノート編集画面 |
| ノートへの試合紐付け | 1件 | 複数件 | 試合選択時 |
| 振り返りテンプレ | 自作1件（プリセットは全員可） | 無制限 | テンプレ追加時 |
| 週次・月次レポート | 基本のみ | 課題別内訳・相関・成績前週比・月次 | 定期レビュー画面 |
| 相関インサイト | × | ○ | インサイト画面 |
| メニュー別推移詳細 | × | ○ | メニューサマリー画面 |
| 目標 | 2件（月次/週次/年間） | 無制限＋シーズン目標・大会目標・カスタム期間・自由指標 | 目標作成時・種別選択時 |
| 推移グラフ | 試合/月 | シーズン/年 | 粒度切替の「シーズン」「年」 |
| 素振りカウンター | 基本無料（インターバル5〜8秒） | インターバル1〜20秒・バイブレーション・バックグラウンド継続 | 素振りの設定画面 |
